# AMG v1.1.6

Patch release preventing Chromium and WebKit from blocking the post-consent `303 See Other` OAuth callback redirect chain (`https://oauth-redirect.googleusercontent.com` -> `https://gemini.google.com`) under `Content-Security-Policy` `form-action`.

## Changes

- **Chromium / WebKit OAuth callback redirect compatibility**: replaces `form-action 'self'` on `/oauth/authorize` consent pages with `base-uri 'none'` inside `default-src 'none'; style-src 'unsafe-inline'; base-uri 'none'; frame-ancestors 'none'`. Chromium (issue `#40923007`) and WebKit evaluate `form-action` across every `302`/`303` redirect hop after an HTML `<form method="post">`, blocking multi-origin OAuth callback redirects even after the server validates the request and issues an authorization code. `default-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, and Go `html/template` auto-escaping remain intact.

## Installation and verification

The release target is **Linux amd64**; source builds require **Go 1.25+**.

Download `agent-mcp-go-v1.1.6-linux-amd64.tar.gz` and `checksums.txt` from [v1.1.6](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.1.6), verify the checksum and follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.6/README.md#quick-start). Preserve existing configuration and credentials.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

See [security](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.6/docs/security.md) and [changes since v1.1.5](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.1.5...v1.1.6).
