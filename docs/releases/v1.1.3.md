# AMG v1.1.3

This release makes AMG comfortable to share between several agents, lets remote browser and desktop clients connect from their own origin, and expires disposable session state. It keeps AMG's module-first architecture and its existing tool contracts.

## Changes

- Task state is serialized per scope instead of globally. The notes and plans of one scope are written under a lock keyed by the resolved scope directory, so agents in different scopes proceed in parallel and one scope is never written twice at once. Review baselines serialize per repository and use per-scope Git refs. A canceled caller releases its lock and never blocks another agent. The lock is process-local.
- `remember` now deletes a task-local note key when its `value` is empty. This keeps the top-level MCP tool surface exactly as it was in v1.1.2 and never touches shared long-term memory.
- `run_command` accepts an optional `workdir`. It is resolved against the configured `default_workdir`, must stay inside `work_root`, and must be an existing directory; a regular file or a missing path is refused. Omitting it keeps the previous default.
- A new `default_workdir` configuration field selects the starting directory for relative paths and for tools that take no explicit directory. It must be an existing directory inside `work_root`; `work_root` remains the access boundary.
- Task state of an anonymous MCP session expires after 30 days without activity. Read-only `recall` and other existing-state reads refresh the session marker, so a read-heavy session keeps its TTL. Explicit scopes and ChatGPT conversation scopes are durable and are never removed by that sweep. Expired scopes are collected at startup and in a sweep that runs at most once an hour, so a long-running daemon keeps cleaning up without a restart.
- A new `allowed_origins` configuration field lists extra browser or desktop client origins that may carry authenticated requests. Each entry is a bare origin with scheme and host, without path, query, fragment, or trailing slash, or `*` to accept every origin. Startup rejects malformed entries. The default is unchanged: only the `public_url` origin is accepted.
- An optional OAuth 2.1 authorization server joins the static Bearer token. It is off unless the new `oauth` block is enabled and covers Google Gemini Web Connected Apps, Claude Web, and ChatGPT with protected resource metadata, authorization server plus OIDC discovery metadata, dynamic client registration, an owner-consent page, PKCE, token exchange, non-rotating refresh, and revocation. Pre-registered clients can use a `client_id` and `client_secret_sha256` instead.
- `/mcp` and `/mcp/stateless` accept both the owner token and OAuth access tokens through the official SDK middleware. A missing or invalid token answers 401 with a `WWW-Authenticate: Bearer` challenge carrying `resource_metadata` and `scope="mcp"`.
- The bootstrap instructions budget rises from 24 KiB to 32 KiB, and the Skills catalog preview stays at 13 KiB. The agent brief now names the default working directory.

The tool count stays identical to v1.1.2 and no second registry or daemon is introduced. Bearer verification and protected-resource / OAuth metadata use the official `github.com/modelcontextprotocol/go-sdk/auth` and `oauthex` packages, `SKILL.md` frontmatter parsing uses `gopkg.in/yaml.v3` with safe UTF-8 rune truncation, and OAuth endpoint throttling promotes `golang.org/x/time` from an indirect to a direct dependency. Bearer authentication is still checked before the Host and Origin values, so a request without a valid token remains unauthorized regardless of its origin.

## Multi-agent operation

Give every concurrent agent its own explicit `scope`, and give every agent that edits the same repository its own `git worktree` checkout; pass that checkout path as the `workdir` of `run_command` or the `directory` of the Git tools. Keep shared services, deployment switches, and configuration files single-writer: an isolated worktree isolates the working tree, not the service behind it.

## OAuth clients

Enable the server by setting `public_url` to the public HTTPS origin and adding `"oauth": {"enabled": true}`. Gemini Web then registers itself through `POST /oauth/register` when its client-ID and client-secret fields are left empty, or uses a client pre-registered in `oauth.clients` when they are filled in. Completing the first connection requires the owner Bearer token on AMG's consent page; afterwards the client refreshes hourly with the same refresh token and keeps its `Mcp-Session-Id`.

OAuth state lives in `<state_dir>/oauth/state.json` and stores only SHA-256 digests. Access tokens, refresh tokens, and dynamic clients are capped at 512, 256, and 128; expired entries are swept on each request; authorization codes and consent tickets are single-use and in memory. See [configuration](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.3/docs/configuration.md#oauth-authorization-server) and [Gemini Web setup](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.3/docs/integrations.md#gemini-web-and-oauth-clients).

## Installation and verification

The release target is **Linux amd64**; source builds require **Go 1.25+**.

Download `agent-mcp-go-v1.1.3-linux-amd64.tar.gz` and `checksums.txt` from [v1.1.3](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.1.3), verify the checksum and follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.3/README.md#quick-start). Preserve existing configuration and credentials; `default_workdir`, `allowed_origins`, and `oauth` are optional and keep their previous behavior when omitted.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

Promotion requires independent review and successful exact-SHA main CI before tagging. The downloaded release is checked in an isolated installation before an atomic, reversible AMG-only upgrade. File-transfer and ingress configuration are unchanged.

See [security](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.3/docs/security.md) and [changes since v1.1.2](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.1.2...v1.1.3).
