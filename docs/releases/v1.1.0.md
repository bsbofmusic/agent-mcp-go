# AMG v1.1.0

AMG is a remote agent workspace over MCP. This version simplifies optional shared-module integration around the shared owner's existing interfaces.

## Changes

- The default path is module discovery → the selected module's tool summaries → exact schema when needed → native invocation. An empty query with `source` lists one module without initializing unrelated targets.
- Directory and exact-schema reads use the canonical shared helper. Unknown tool counts are omitted. Module purpose metadata is not invented when the owner supplies only names and URLs.
- The global schema index, TTL/background refresh, custom BM25, bilingual business dictionary and duplicate SDK `ListTools` transport are removed. Unscoped search remains a bounded literal fallback and reports failures from the current request.
- The small SDK `CallTool` adapter remains because the helper's text envelope and output cap do not preserve native result blocks directly. Content, images, resources, structured content, `isError` and result metadata retain their existing contract.

## Compatibility

Public tool names and the three `shared_mcp_*` compatibility entries remain available. New callers should use the module-first interface. `force_refresh` is accepted for compatibility; listings are already request-local. `score` is retained as a wire field, not a semantic relevance estimate. Cross-module natural-language ranking and cache-hit latency are no longer features of the interface.

No source inventory, business owner map, registry, watcher, daemon, database or dependency is added. Module add/remove and schema changes are observed at the next explicit lookup without an AMG restart. This does not replace a client's already loaded context in place or establish notification support.

Workspace execution, file transfer, native attachment/review contracts, task continuity, diagnostics, and security boundaries are unchanged. Real client experience remains a user acceptance step.

## Installation and verification

The supported release target is **Linux amd64**. Source builds require **Go 1.25+**.

Assets:

- `agent-mcp-go-v1.1.0-linux-amd64.tar.gz`
- `checksums.txt`

Download the [v1.1.0 release](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.1.0), verify its checksum, and follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.0/README.md#quick-start). Preserve existing configuration and credentials; fresh-install setup refuses to overwrite them.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

Independent audit binds to the final candidate code and documentation before promotion. Main-branch CI must pass on the exact release commit before tagging. Downloaded release assets need checksum verification and an isolated install smoke. Skipped opt-in tests are not live evidence.

See [integrations](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.1.0/docs/integrations.md) and [changes since v1.0.3](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.0.3...v1.1.0).
