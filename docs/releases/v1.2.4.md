# AMG v1.2.4

## Background

Four surgical fixes, each reported from real use rather than from a rewrite plan. `grep` refused a single file path, so an agent that knew the exact file had to widen the search to its directory. `skills_list` sent its payload twice, because a nil text result made the SDK serialize the whole structured object into one text block. `recall` documented `key` / `prefix` filtering that its input schema did not accept. And a deployment without `skills_root` was told that Skills were "currently unavailable", which reads as a fault and invites a retry loop.

Runtime capabilities and the 40-tool catalogue are unchanged. No new daemon, cache layer, second registry, automatic module discovery, or global tool denylist is added, and `session_id` stays the 46-bit numeric handle that Gemini Web already round-trips.

## Changes

- **`grep` accepts a single regular file path.** A selected file is searched directly, through the same `os.Root` boundary, regular-file descriptor check, `binaryExtensions` skip, `max_search_file_bytes` limit (with the same bounded read and NUL check), and `ignoreCase` / `context` / `filesOnly` / `maxResults` / output-budget handling as a directory walk. Output lines keep the exact `path:line:content` format, with `-` for context lines. `glob` keeps directory-only semantics, and `searchWalk`'s directory contract is unchanged. A selected path that is neither a directory nor a regular file returns `search path is not a directory or regular file`. Symlinked entries are still refused rather than resolved, so the single-file branch cannot leave `work_root` even if a link is created after inspection. One deliberate asymmetry is preserved and tested: an explicitly named file is searched even inside an ignored directory, matching the existing rule that a selected root is never ignore-filtered.
- **`skills_list` stops emitting its payload twice.** The handler now returns the compact summary text explicitly, so the text block is the summary alone while `structuredContent` still carries both `skills` and `content`. A full 199-Skill catalogue drops from 152,293 bytes of text to 64,783 bytes (−57.5%) with the structured payload byte-identical, so `OutputSchema` and structured clients are unaffected. An empty catalog or an unmatched search now returns a readable line instead of an empty string.
- **`recall` gains the `key` and `prefix` filters its description promised.** `RecallInput` adds optional `key` and `prefix`; an exact `key` wins when both are supplied, `prefix` matches by string prefix, and omitting both returns the whole note set as before. Filtered output stays two-space-indented JSON, no match returns `{}`, and the per-scope state isolation is unchanged.
- **An unset `skills_root` reads as an optional integration, not a fault.** Both instruction builders now branch on `cfg.SkillsRoot == ""` and emit a plain statement that Skills are not configured on this deployment and that the file, shell and Git tools work without them, with no retry prompt. A configured root that cannot be read is still reported as a real failure. `skills_list` and `skills_read` return `skills_root not configured` instead of a raw filesystem errno, and the initialize compact-index note is only emitted when a catalogue is actually served.
- **Remove single-host wording from generated text.** `the agent OS user` becomes the non-root account that runs the server, and the fixed `Obsidian brain/ pages, then raw/transcripts/agentsview/` archive path becomes an optional deployment-configured archive with those products named only as an example. The same correction is applied to the `get_agent_brief` saved-state paragraph and to `docs/integrations.md`. This repository's own rules still arrive through the unchanged `AGENTS.md` project-instruction injection.
- Version number is `1.2.4`.

## Compatibility

- No breaking changes. The 40 tool names, existing input fields, return shapes, and `annotations_mode` behavior are unchanged. `recall`'s `inputSchema` gains two optional properties (`key`, `prefix`), and `grep` accepts a path shape it previously rejected; both are additive.
- `skills_list` text output is shorter by design; `structuredContent` is unchanged, and a client that read the text block as serialized JSON now receives the summary text instead. Agents that parsed `structuredContent` need no change.
- The MCP protocol version, `/mcp/stateless` semantics, the OAuth flow, and the `<state_dir>/oauth/state.json` format are unchanged.
- No configuration change is required. Deployments that set `skills_root` behave as before apart from the improved wording; deployments that leave it empty get the new optional-integration text instead of an unavailable notice.
- `session_id` type and range are untouched.

## Installation and verification

Linux amd64. Building from source requires Go 1.25+. Download the archive and checksums from [v1.2.4](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.2.4), follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.2.4/README.md), and preserve your configuration and credentials.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

## Verification

From a source checkout of this tag:

```sh
CGO_ENABLED=0 go test -count=1 -run 'TestGrepSingleFile|TestGlobKeepsDirectoryOnlySemantics|TestSkillsListTextIsSingleCompactSummary|TestCanonicalSkillsRequireConfiguredRoot|TestRecallKeyAndPrefixFiltering|TestUnconfiguredSkillsAndMCPStayClearlyUsable|TestInitializeInstructionsDescribeUnconfiguredSkillsAsOptional' -v .
```

Against a running deployment (replace the base URL; the token is read from its file and never printed), check the four fixes:

```sh
TOKEN=$(cat "${AGENT_MCP_GO_TOKEN_FILE:-$HOME/.config/agent-mcp-go/mcp-token}")
BASE=http://127.0.0.1:3100
call() {
  curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
    -d "{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/call\",\"params\":{\"name\":\"$1\",\"arguments\":$2}}" \
    "$BASE/mcp/stateless"
}
# 1. A single file path is searchable and keeps the path:line:content format.
call grep '{"path":"/etc/hostname","pattern":"."}' | head -c 400; echo
# 2. skills_list text is the compact summary, not the serialized structured object.
call skills_list '{}' | python3 -c 'import sys,json; r=json.load(sys.stdin)["result"]; t="".join(c.get("text","") for c in r["content"]); s=json.dumps(r.get("structuredContent",{})); print("text_bytes",len(t),"structured_bytes",len(s),"first_char",t[:1])'
# 3. recall filtering works and an unmatched filter returns {}.
call recall '{"scope":"amg-v124-acceptance","key":"missing"}' | head -c 200; echo
# 4. Live settings and the untouched annotation mode.
call settings_get '{}' | grep -o 'annotations_mode=[a-z]*\|skill_index_max_bytes=[0-9]*\|max_shell_sessions=[0-9]*'
```

## Rollback

Roll back the deployment, not only the process. A Nix profile switch is part of a binary upgrade, so the layers must move together.

1. Select the previous profile generation and restart from an independent unit. This host runs AMG from the `agent-cli` profile: v1.2.3 is generation 27, and v1.2.4 adds the next generation. The agent runtime cannot restart its own control plane, so start the rollback from a separate `systemd-run --user` unit (or an SSH session) rather than from inside the agent session:

   ```sh
   nix profile history --profile /home/agent/.local/state/nix/profiles/agent-cli
   systemd-run --user --unit=amg-rollback --wait --collect \
     nix profile rollback --profile /home/agent/.local/state/nix/profiles/agent-cli --to 27
   systemctl --user restart agent-mcp-go.service
   ```

   The transient unit runs with the user manager's environment; use an absolute `nix` path such as `~/.nix-profile/bin/nix` if the manager's `PATH` does not include it. After the restart, verify the running binary instead of only the profile: `serverInfo.version` must be `1.2.3`, `/proc/<MainPID>/exe` must not end in ` (deleted)`, and `/healthz` must answer before the rollback is considered complete:

   ```sh
   PID=$(systemctl --user show -p MainPID --value agent-mcp-go.service)
   readlink "/proc/$PID/exe"    # no " (deleted)" suffix
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3100/healthz
   TOKEN=$(cat "${AGENT_MCP_GO_TOKEN_FILE:-$HOME/.config/agent-mcp-go/mcp-token}")
   curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"rollback-check","version":"0"}}}' \
     http://127.0.0.1:3100/mcp | grep -o '"version":"1\.2\.3"'
   ```

2. Revert the deployment pin. Set `/home/agent/code/host-infra/packages/agent-mcp-go.nix` back to `version = "1.2.3"` with its published hash `sha256-No/ZUWm2wXb6bRD5XV4+CCH9i6JzB4H9JwUBrPBl42Y=` and commit it. Without this step the next `tg --maintenance` run upgrades the profile to v1.2.4 again.

3. Restore any live setting that was hot-tuned for this release. `settings_update` writes to the configuration file, and a v1.2.3 binary reads the same keys, so a value such as `skill_index_max_bytes` or `max_shell_sessions` survives a rollback. Reinstate the previous value only if you want the old number back, and do it through `settings_update` after the rollback restart, for example:

   ```json
   {"name": "settings_update", "arguments": {"skill_index_max_bytes": 40000, "max_shell_sessions": 8}}
   ```

No configuration change is required and no memory keys are involved in this release. v1.2.3 ignores nothing in the 1.2.4 configuration, and v1.2.4 adds no new configuration keys.

See the [configuration reference](../configuration.md) and the [comparison with v1.2.3](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.2.3...v1.2.4).
