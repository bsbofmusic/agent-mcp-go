# AMG v1.0.3

AMG is a remote agent workspace over MCP. This patch improves tool relevance and adds private request-stage diagnostics.

## Changes

- Tool search keeps field boundaries rather than treating descriptive text and schema vocabulary as one pool of execution evidence. Repeated field terms saturate; output-schema mentions have a weak recall role. Fixed Chinese and English cases preserve capability-report intent and parameter-only discovery.
- Authenticated MCP traffic has server-generated request identifiers with HTTP/RPC correlation, review lookup/lock/baseline phases, handler dispatch, cancellation and completion timings. Only allowlisted server labels are logged. Commands, arguments, paths, scopes, client identifiers, headers, results and raw errors are omitted.
- HTTP completion is labelled `returned`, independently of the RPC success/error outcome. Diagnostics do not retry requests or commands and do not prove the cause of any earlier timeout.

## Installation and verification

The release target is **Linux amd64**; source builds require **Go 1.25+**.

Assets:

- `agent-mcp-go-v1.0.3-linux-amd64.tar.gz`
- `checksums.txt`

Download the [v1.0.3 release](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.0.3), verify the checksum, and follow the [README quick start](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.0.3/README.md#quick-start). Preserve existing configuration and credentials; fresh-install setup refuses to overwrite them.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

Main-branch CI must pass on the exact release commit before tagging. Optional live tests require an explicit configuration and opt-in; skipped tests are not live evidence.

## Compatibility and limits

No route owner, persistent registry, database or dependency is added. Workspace, transfer, attachment, review and checkpoint interfaces are unchanged. Search regressions do not establish a new real-client Top3 rate or end-to-end agent latency. Host attachment authorization, UI rendering and client experience remain separate manual checks.

Request records use the existing process logger; retention follows the operator's journal/log configuration. See [security](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.0.3/docs/security.md), [integrations](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.0.3/docs/integrations.md), and [changes since v1.0.2](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.0.2...v1.0.3).
