# AMG v1.2.3

## Background

A workspace mutation in a large Git repository ran an unbounded `git add -A` review snapshot for more than 13 minutes. Inside a 400 MiB cgroup that snapshot exhausted memory, drove the host into swap, and timed out every concurrent tool call until it finished. v1.2.3 bounds that snapshot, makes a degraded baseline explicit instead of blocking, and fixes the surrounding per-request costs observed at the same time. Runtime capabilities and the 40-tool catalogue are unchanged.

## Changes

- The review baseline snapshot now runs under `review_baseline_timeout_seconds` (default 10, range 1–120). On timeout, failure, or a `review_baseline_skip_paths` match, the baseline degrades to `HEAD^{tree}` and the mutation proceeds instead of failing. The `show_changes` workspace snapshot runs under the same deadline; when it expires, `show_changes` fails with an actionable error (narrow the directory argument or raise the setting) instead of returning a partial diff, and it writes no review ref. Once a degradation has been written as the `project-open` ref, that ref lives in the repository and short-circuits later baseline checks, so the cheap path survives process restarts. The fixed 10-minute cooldown is keyed by repository path, so later baseline checks for that repository in the same process take the cheap path too, including new task scopes; it carries weight only when writing that ref failed. The cooldown lives in process memory and a restart clears it, but a restart never removes a written ref. Every degradation and every `show_changes` snapshot timeout is logged as an `amg_review_baseline` request-log event with the repository and reason, plus an `error` field when there is one. `review_baseline_skip_paths` lists absolute prefixes inside `work_root` whose projects never run the full-workspace snapshot; matching is a purely lexical prefix comparison, so entries must use the physical path form from `git rev-parse --show-toplevel`, otherwise they silently do not match. A degraded baseline also makes `show_changes since=project_open` diff against `HEAD^{tree}` (or the empty tree in an unborn repository), so that diff includes the user's pre-existing uncommitted changes; this is a deliberate tradeoff of the cheap path.
- The `run_command` file-rule now reads its directory from `workdir`, so `run_command` mutations capture a baseline in the directory they actually run in. Previously the empty string was used, which skipped the baseline for `run_command`.
- Initialization instructions now carry a bounded Skills index: each description is truncated rune-safely to `skill_index_entry_bytes` (default 160, range 80–400) with an ellipsis, the entry lines stop at `skill_index_max_bytes` (default 24000, range 1 KiB–1 MiB), and the header points at `skills_list` for the complete inventory and full descriptions. The section title, explanation paragraph, and preview line are counted outside that entry-line budget, so with the defaults the whole Skills section measures about 24,203 bytes — 0.85% over the entry budget while total output remains bounded. `get_agent_brief` keeps the complete catalogue under `max_output_bytes`.
- A Skills catalogue cache hit now compares only `SKILL.md` inode, size, mtime, and ctime, so a hit opens no file. Any metadata change falls back to the frontmatter fingerprint, and same-size edits with a restored mtime still invalidate the cache.
- `settings_get` and `settings_update` cover all 18 live settings: 15 numeric settings, `review_baseline_skip_paths`, `annotations_mode`, and `bootstrap_files`. The new review and index settings apply without a restart. A degraded `project-open` ref is persisted in the repository and keeps later calls on the cheap path; the 10-minute cooldown is process-local and only covers a failed ref write.
- The remaining input-schema descriptions that named other tools (`import_host_file`, `mcp_search_tools`, `shared_mcp_tools`) now describe their own parameter instead of referring to another tool name.
- Origin-denied 403 responses carry `Vary: Origin`, including CORS preflight rejections, so a shared cache cannot replay a rejection for a later allowed origin.
- The OAuth authorization-server metadata document omits the `jwks_uri` member when no JWKS document is served. Every other field, value, and the document order are unchanged.
- The tracked template `systemd/agent-mcp-go.service.example` now sets `MemoryHigh=400M`, `MemoryMax=800M`, and `MemorySwapMax=512M`, with a comment explaining that review snapshots and Shell sessions are memory-hungry, and adds `LimitNOFILE=512` to match the live unit. The effective host unit is the untracked host-local deployment file `systemd/agent-mcp-go.service` (excluded by `.gitignore` line 20, `/systemd/*`), and `~/.config/systemd/user/agent-mcp-go.service` is a symlink to it; that file already carries the deployed memory keys plus `TasksMax=80`, `LimitNOFILE=512`, and `Environment=CGO_ENABLED=0`. Because the deployed file is not tracked, the memory-key change does not appear in Git history and other machines must apply it by hand. v1.2.3 does not restart or reload the running service.
- Version number is `1.2.3`.

## Compatibility

- No breaking changes. The 40 tool names, existing input fields, return shapes, and the `annotations_mode` behavior are unchanged; `settings_update`'s `inputSchema` gains four optional properties (`review_baseline_timeout_seconds`, `review_baseline_skip_paths`, `skill_index_entry_bytes`, `skill_index_max_bytes`), and three existing parameters (`import_host_file`'s `file`, `mcp_search_tools`' `source`, `shared_mcp_tools`' `server`) get clearer descriptions. The MCP protocol version, `/mcp/stateless` semantics, and the OAuth flow are unchanged, and the `<state_dir>/oauth/state.json` format is unchanged.
- All four new configuration keys are optional. Configurations without them keep the documented defaults. Older binaries ignore unknown keys, so the same file can be reused during a rollback.
- Initialize instructions are shorter; the Skills index is a subset by design. Agents that need a Skill's full description call `skills_list`, which returns the complete catalogue. The initialize response itself can be larger or smaller than before depending on the number of installed Skills.
- The authorization-server metadata document no longer contains an empty `jwks_uri`. Clients that require the member for a server that publishes no keys are unaffected, because the value was empty and unusable.
- The memory limits are declarative unit settings: they take effect on the next `systemctl --user daemon-reload` and restart of `agent-mcp-go.service` after the unit file is updated. The tracked template change alone touches no running service, and v1.2.3 requires no configuration change.

## Installation and verification

Linux amd64. Building from source requires Go 1.25+. Download the archive and checksums from [v1.2.3](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.2.3), follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.2.3/README.md), and preserve your configuration and credentials.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

## Verification

From a source checkout of this tag:

```sh
CGO_ENABLED=0 go test -count=1 -run 'TestReviewBaseline|TestRunCommandBaseline|TestInitializeInstructions|TestAuthServerMetadata|TestOriginDenied|TestCORSPreflight|TestSkillsCatalogCache' -v .
```

Against a running deployment (replace the token and base URL), check the new settings and the cheap paths:

```sh
TOKEN=$(cat "${AGENT_MCP_GO_TOKEN_FILE:-$HOME/.config/agent-mcp-go/mcp-token}")
BASE=http://127.0.0.1:3100
# 18 live settings, including the four new keys.
curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"settings_get","arguments":{}}}' \
  "$BASE/mcp/stateless" | grep -o 'review_baseline_timeout_seconds=[0-9]*\|review_baseline_skip_paths=[0-9]*\|skill_index_entry_bytes=[0-9]*\|skill_index_max_bytes=[0-9]*'
# No empty JWKS URI in the metadata document.
curl -s "$BASE/.well-known/oauth-authorization-server" | grep -c jwks_uri
# An origin-denied 403 advertises Vary: Origin.
curl -sD- -o /dev/null -X POST -H "Authorization: Bearer $TOKEN" \
  -H 'Origin: https://example.invalid' "$BASE/mcp" | grep -i '^vary:'
```

For a large repository, set `review_baseline_skip_paths` to its path (or leave the default 10-second timeout in place) and confirm a mutation still returns promptly while the request log records one `amg_review_baseline` event.

## Rollback

Roll back the deployment, not only the process. A Nix profile switch is part of a binary upgrade, so the layers must move together.

1. Select the previous profile generation and restart from an independent unit. This host runs AMG from the `agent-cli` profile: v1.2.2 was generation 26, and v1.2.3 adds the next generation. The agent runtime cannot restart its own control plane, so start the rollback from a separate `systemd-run --user` unit (or an SSH session) rather than from inside the agent session:

   ```sh
   nix profile history --profile /home/agent/.local/state/nix/profiles/agent-cli
   systemd-run --user --unit=amg-rollback --wait --collect \
     nix profile rollback --profile /home/agent/.local/state/nix/profiles/agent-cli --to 26
   systemctl --user restart agent-mcp-go.service
   ```

   The transient unit runs with the user manager's environment; use an absolute `nix` path such as `~/.nix-profile/bin/nix` if the manager's `PATH` does not include it. After the restart, verify the running binary instead of only the profile: `serverInfo.version` must be `1.2.2`, `/proc/<MainPID>/exe` must not end in ` (deleted)`, and `/healthz` must answer before the rollback is considered complete:

   ```sh
   PID=$(systemctl --user show -p MainPID --value agent-mcp-go.service)
   readlink "/proc/$PID/exe"    # no " (deleted)" suffix
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3100/healthz
   TOKEN=$(cat "${AGENT_MCP_GO_TOKEN_FILE:-$HOME/.config/agent-mcp-go/mcp-token}")
   curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"rollback-check","version":"0"}}}' \
     http://127.0.0.1:3100/mcp | grep -o '"version":"1\.2\.2"'
   ```

2. Revert the deployment pin. Set `/home/agent/code/host-infra/packages/agent-mcp-go.nix` back to `version = "1.2.2"` with its published hash `sha256-QWysfqXgohbdnkxIRLg9h+0/ipvNQbn3SU3CDlf3vmM=` and commit it. Without this step the next `tg --maintenance` run upgrades the profile to v1.2.3 again.

3. Remove the memory caps by hand if the old behavior is required. The tracked template `systemd/agent-mcp-go.service.example` had no `Memory*` lines in v1.2.2, so there is nothing to restore from that file. The limits in effect come from the host-local deployment file `systemd/agent-mcp-go.service`, which `.gitignore` line 20 excludes (`/systemd/*`); the installed unit `~/.config/systemd/user/agent-mcp-go.service` is a symlink to that file. Edit the deployment file to drop `MemoryHigh`, `MemoryMax`, and `MemorySwapMax`, then reload and restart:

   ```sh
   systemctl --user daemon-reload
   systemctl --user restart agent-mcp-go.service
   ```

   A profile rollback alone leaves those caps in place.

No configuration change is required. Keep the v1.2.3 configuration file: v1.2.2 ignores the four new keys, the `Vary` header and the metadata change are response-level only, and rollback restores the unbounded review baseline. If a project was added to `review_baseline_skip_paths` only for v1.2.3, remove the entry from the configuration to avoid silent drift on the next upgrade.

See the [configuration reference](../configuration.md) and the [comparison with v1.2.2](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.2.2...v1.2.3).
