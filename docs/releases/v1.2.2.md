# AMG v1.2.2

## Background

Google Gemini Web's Connected Apps MCP integration requires the host to discover standard authorization server and protected resource metadata, complete PKCE authorization in a browser, and read complete, reviewable tool metadata from `tools/list`. v1.2.2 tightens tool descriptions and titles to that standard, adds browser CORS preflight for the MCP entry points, and ships a repeatable nine-check acceptance script. Runtime capabilities and the tool count are unchanged.

## Changes

- Tool descriptions now state function only: behavior instructions, cross-tool references, and uppercase warning words are gone. The 40 tool names and input schemas are unchanged.
- All 40 tools carry a top-level `title`, so `tools/list` no longer emits tools without a title. In `default` mode every tool now declares all four safety hints explicitly; `settings_get`, `settings_update`, and `transfer_prepare` previously returned no annotations and fell back to client defaults. `trusted` mode is unchanged: it still advertises the whole catalogue as read-only, non-destructive, and closed-world.
- When `allowed_origins` is non-empty, `/mcp`, `/mcp/stateless`, and `/` support browser CORS: whitelisted preflight returns 204 with the full `Access-Control-*` header set, unknown origins get 403, actual responses expose `Mcp-Session-Id` and `WWW-Authenticate`, and `Access-Control-Allow-Credentials` is never sent. An empty `allowed_origins` keeps v1.2.1 behavior.
- New `scripts/verify-gemini-web.sh`: nine checks covering health, OAuth metadata, the anonymous 401 challenge, `initialize` and `tools/list` inside the session, stateless GET, and CORS. It exits 1 on any failure and never prints the token.
- Documentation adds the Gemini Web compatibility table, the consent-page owner passkey, and CORS behavior.
- Version number is `1.2.2`.

## Compatibility

- No breaking changes. The 40 tool names, input schemas, return shapes, and behavior are unchanged; the MCP protocol version, `/mcp/stateless` semantics, and the OAuth flow are unchanged.
- Existing OAuth access tokens, refresh tokens, and dynamic clients keep working; the `<state_dir>/oauth/state.json` format is unchanged.
- Deployments with an empty `allowed_origins` emit no new headers and upgrade without a configuration change.
- New tool `title` and description text change the tool metadata cached by hosts; refresh the host tool list once after upgrading.

## Installation and verification

Linux amd64. Building from source requires Go 1.25+. Download the archive and checksums from [v1.2.2](https://github.com/bsbofmusic/agent-mcp-go/releases/tag/v1.2.2), follow the [README](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.2.2/README.md), and preserve your configuration and credentials.

```sh
umask 077
CGO_ENABLED=0 go test -count=1 ./...
CGO_ENABLED=0 go vet ./...
CGO_ENABLED=0 go build -buildvcs=false -trimpath -o agent-mcp-go .
```

## Verification

Run the nine checks against a running deployment from a source checkout of this tag; the script ships with the repository, not inside the binary archive. It reads `$HOME/.config/agent-mcp-go/mcp-token` by default and never prints the token:

```sh
scripts/verify-gemini-web.sh
```

For a temporary instance or a custom address:

```sh
scripts/verify-gemini-web.sh --base-url http://127.0.0.1:3201 \
  --token-file /tmp/amg-token --origin https://gemini.google.com
```

The checks are, in order: `/healthz`; authorization server metadata including the `/mcp` variant; protected resource metadata including the `/mcp` variant; the anonymous `POST /mcp` 401 with a `resource_metadata` challenge; `initialize` in a session (printing the negotiated protocol version) and `tools/list` (40 tools, annotation completeness, missing titles); GET `/mcp/stateless` 405; CORS preflight for a whitelisted and a non-whitelisted origin (printing ACAO). Each check prints `PASS` or `FAIL`, and any failure exits 1.

## Rollback

Roll back the deployment, not only the process. A Nix profile switch is part of this upgrade, so three layers must move together.

1. Select the previous profile generation and restart from an independent unit. This host runs AMG from the `agent-cli` profile: v1.2.1 was generation 25, and v1.2.2 adds the next generation. The agent runtime cannot restart its own control plane, so start the restart from a separate `systemd-run --user` unit (or an SSH session) rather than from inside the agent session:

   ```sh
   nix profile rollback --profile ~/.local/state/nix/profiles/agent-cli --to 25
   systemctl --user restart agent-mcp-go.service
   ```

   Then verify `serverInfo.version` reports `1.2.1`, `/proc/<MainPID>/exe` has no `(deleted)` suffix, and `/healthz` returns `ok`.
2. Revert the deployment pin. Set `packages/agent-mcp-go.nix` back to `version = "1.2.1"` with its published hash and commit it. Without this step the next `tg --maintenance` run upgrades the profile to v1.2.2 again.
3. No configuration change is needed. v1.2.1 accepts the same configuration keys, and an existing `allowed_origins` list is simply unused for CORS there.

After rollback, browser cross-origin calls return to v1.2.1 behavior (no `Access-Control-*` headers), while tool descriptions and `title` revert to the previous text without affecting calls. OAuth state and issued tokens remain valid; to revoke every grant, stop the service and delete `<state_dir>/oauth/state.json`.

See [configuration](https://github.com/bsbofmusic/agent-mcp-go/blob/v1.2.2/docs/configuration.md) and [changes](https://github.com/bsbofmusic/agent-mcp-go/compare/v1.2.1...v1.2.2).
